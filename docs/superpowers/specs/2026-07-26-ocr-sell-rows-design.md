# OCR 매도 원본 행 보존 설계

## 문제

거래 이미지의 매도 표는 세 행으로 구성된다. 앞선 행들이 `- / -`이고 마지막 행에만 주문이 있으면 Gemini가 빈 행과 함께 마지막 유효 행까지 생략해 `sell: []`를 반환하는 사례가 있다. 2026-04-24 입력 이미지에서는 `112.79 / 남은전부`가 보이지만 KISTA 요청에서 매도 주문이 누락됐다.

현재 Java 변환은 Gemini가 반환한 `sell` 배열만 사용한다. 배열이 비면 경고만 발생하므로 이미지에 존재하는 주문을 복구할 근거가 없다.

## 목표

- Gemini가 매도 표의 세 물리적 행을 순서대로 반환하게 한다.
- `sell` 배열이 주문을 누락해도 원본 행에 값이 있으면 이를 사용한다.
- 실제 매도 표 세 행이 모두 비어 있으면 매도 주문을 생성하지 않는다.
- 보유수량, 종가, 평단 등 다른 값으로 매도 주문을 추측하지 않는다.

## 설계

Gemini JSON 스키마에 `sell_rows`를 추가한다. `sell_rows`는 매도 표의 첫째, 둘째, 셋째 행을 항상 순서대로 담는 고정 길이 배열이다. `-` 또는 빈 셀은 `null`로 표현하며 `남은전부`, `전부`, `ALL`은 `ALL`로 정규화한다.

```json
{
  "sell": [],
  "sell_rows": [
    {"price": null, "qty": null},
    {"price": null, "qty": null},
    {"price": 112.79, "qty": "ALL"}
  ]
}
```

파서는 다음 우선순위를 적용한다.

1. `sell`에 유효 주문이 하나 이상 있으면 기존 `sell`을 사용한다.
2. `sell`이 비어 있으면 `sell_rows`에서 가격이나 수량이 하나라도 있는 행만 주문으로 변환한다.
3. `sell_rows`도 모두 비어 있거나 필드 자체가 없으면 빈 매도 주문 목록을 유지한다.

이전 Gemini 응답에는 `sell_rows`가 없으므로 필드는 선택적으로 역직렬화한다. 기존 응답과의 하위 호환성을 유지한다.

## 오류 및 관측

`sell`이 비었지만 `sell_rows`에서 주문을 복구하면 로그와 OCR 경고 알림을 남긴다. 두 필드가 모두 비었을 때는 현재의 빈 매도 결과 경고를 유지한다. 복구 과정에서 보유수량이나 오른쪽 성과 표의 값은 사용하지 않는다.

## 테스트

- `sell=[]`이고 세 번째 `sell_rows`에 `112.79 / ALL`이 있으면 매도 주문 한 건으로 복구한다.
- `sell=[]`이고 `sell_rows` 세 행이 모두 `null`이면 매도 주문은 비어 있다.
- 기존 `sell`에 주문이 있으면 이를 우선하고 `sell_rows`로 중복 생성하지 않는다.
- 기존처럼 `sell_rows`가 없는 응답도 정상 파싱한다.
